# 深海花园：放松、漫游与拍照

> 后续指令已调整范围：当前阶段只做美术、光效、场景体验，不开发玩法或拍照流程。WebGL 1 路线已废弃，实际工程直接复用 Cold Smoke 的 WebGPU / WebGL2 核心。以下为历史提案，当前实施以 ../plans/2026-11-20-cold-smoke-scene.md 为准。

日期：2026-11-20。状态：设计提案，待用户评审；不是已经实现或通过真机验收的版本。已完成独立实施审阅，结论：没有阻碍制定实施计划的重要遗漏；美景质量仍必须在 P1 样片中实际验收。

## 1. 已确认的方向与设计取舍

用户要求重新设计开发路线与实现方案，做一个深海放松 / 漫游 / 拍照的休闲小游戏。承接上轮讨论，发行目标是小红书小工具。用户明确希望玩家三分钟后记住「瑰丽的海底世界美景」，并同意查看浏览器界面草图。

因此优先级是：海底景色与氛围 > 舒适且稳定的手机体验 > 拍照效果 > 内容数量。首版的趣味来自发现新视角、等待生物游过、选择构图，并把照片带走。没有任务栏、集章、稀有度、评分、货币、氧气、死亡、签到和强制分享。

以下均为设计者建议，尚未被用户单独确认：竖屏优先；一个连续小花园而非大地图；自动巡游为默认；允许受约束的手动漫游；首版提供一个完整景区、三段景观；原生 WebGL 1 实现；不依赖后台服务或付费媒体生成。

本轮交付是本设计与可点击界面草图。产品实现需在设计评审后推进。草图中的海底为 SVG 构图示意，不代表最终渲染质量或性能。

## 2. 定位与前三分钟

一句话：随时潜入一座瑰丽、安静的小型海底花园，随水流漫游，拍下喜欢的瞬间。

| 体验时间 | 玩家看到什么 | 可以做什么 |
| --- | --- | --- |
| 打开至准备就绪 | 简洁静态海底首屏，只有名称、进入按钮与具体准备状态 | 不用阅读教程；无声也能理解用途 |
| 进入后 0–20 秒 | 柔和阳光穿过海藻，前景叶片和远处岩拱形成深度 | 不操作也会慢慢向前；拖动看看四周 |
| 20–60 秒 | 游过岩拱，海面亮带展开，一只蝠鲼从上方滑过 | 停驻、改变视角，按下相机留下照片 |
| 60–120 秒 | 镜头来到鲸尾石像前，鱼群绕行，远处能看见紫色微光 | 接管游动，靠近喜欢的构图；随时回到巡游 |
| 120–180 秒 | 进入浅紫洞口和发光珊瑚边缘，再缓慢返回开阔海域 | 拍照、看照片、保存，或者继续看景 |

时间是无操作巡游的编排目标，不是玩家倒计时。每段都有长停留点；生物事件循环出现，不让玩家因为错过一个瞬间而焦虑。各景观从第一次进入即开放，没有解锁门槛。

## 3. 场景规模与视觉标准

首版一个约 60 × 80 米的连续景区，使用弯曲动线与岩壁遮挡连接三段景观。不是三张割裂的背景，也不生成无限世界。此尺寸为内容设计初值，可由实现者按视距与预算调整。

1. **光隙海藻林**：青绿到深蓝的纵深，近处海藻遮挡、中景鱼群、远景岩拱；承担第一眼和首次拍照。
2. **鲸尾静庭**：石制鲸尾为雕塑主体，保留现有项目辨识度；蝠鲼和鱼群穿行，光线最通透；承担停驻与主视觉构图。鲸尾明确是雕塑，不冒充真实鲸鱼。
3. **微光珊瑚湾**：较明亮的洞口与紫色珊瑚，不做全黑狭窄洞窟；发光色控制在局部；承担色彩变化和旅程收尾。

首版生物只有蝠鲼、小鱼群和水母三类；先把轮廓、运动和出现位置做好。沉船、大型鲸鱼和更多景区进入后续候选，避免首版分散美术资源。

画面必须具备：前中远三层；有可识别主体；缓慢水流；局部光纹；生物自然游动；每段至少两个适合竖屏的取景位置。低档可以减少数量和特效，但不能只剩没有主体的蓝色空地。

风格为柔和的半写实幻想海底。避免廉价霓虹、屏幕满是粒子、过饱和荧光色、大面积硬质低模山体、漂浮文字、厚重游戏 HUD。现有程序化造型是起点，不能因为“全部由代码生成”而拒绝必要的本地小贴图；若后续确需外部素材，先确定授权来源。本轮不下载或生成媒体。

## 4. 漫游与舒适性

默认自动巡游：约三分钟的平滑环线，低速、固定水平姿态、对景观短暂停驻。拖动屏幕只改变视线，不立即打断位置巡游；松手后保留朝向，点击「看向前方」才缓慢归正。

「自己游」切换到手动模式：左下虚拟摇杆只控制水平移动；画面其余非按钮区域拖动看四周。右下相机与摇杆分区，使用触点 ID 区分手势。首次仅出现一次简短提示。没有独立上浮、下潜、冲刺和翻滚操作。

高度沿区域的安全高度带平滑变化，边界以岩石、雾和缓慢阻尼提示。使用简单圆形 / 胶囊体障碍避免穿过岩拱和鲸尾；场景无需任意洞穴穿行或全地形物理。手动停止立即减速，移动速度约 0.6–1.5 米/秒，初始水平视角以竖屏构图为准，避免大幅广角畸变。

回到「随流巡游」时，先找可达的路线锚点，通过安全短路径回到巡游线；如果短路径被障碍阻断，使用约 400 毫秒淡出淡入回到锚点，不硬穿岩石，不高速飞过去。返回动作可取消，拍照不会触发自动归位。

减少动态设置关闭镜头漂移与自动朝向变化，降低粒子；可选择停驻看景。声音默认在点击进入后轻柔开启，按钮可一键静音；静音与动态偏好可保存。切后台暂停模拟和声音，回来先停驻，由玩家点击继续，避免镜头和音频突然跳动。

## 5. 拍照闭环

相机按钮进入取景模式，暂停位置巡游，保留拖动构图，生物继续缓慢运动。玩家可在 9:16 和 3:4 间切换，预览框外使用遮罩；导出严格匹配框内视野，不扩展出取景时看不到的内容。只有原色和一个轻微柔光选项，不堆滤镜。

按快门时记录相机、模拟时间和曝光参数，同帧渲染无 UI 的画面；生成照片后暂停场景和声音调度，进入照片预览。预览支持「继续拍」「保存相册」「发笔记」；发布由玩家主动触发，绝不自动发送。作品默认无大水印，可选极小的地点与日期标签。

导出默认长边 1440 像素，低档 1080 像素；设渲染目标像素与显存上限，分配或导出失败改为当前安全分辨率，再失败保留预览并提示重试。JPEG 优先，实际 MIME 能力检测，必要时 PNG。不承诺 4K 或提高几何精度。快门过程锁住重复点击，结束释放临时缓冲和失效对象 URL。

技术路径：渲染至受控离屏 framebuffer → readPixels → 垂直翻转 → Canvas 2D 合成可选标签 → 图片编码 → 临时文件。无需开启长期 preserveDrawingBuffer；按下快门才执行读回。首次验证必须覆盖黑图、上下颠倒、颜色偏差、竖横屏与导出失败。

首版「最近照片」最多 12 张，原图不放进 Storage 的 JSON。文件系统可用时保存原图和小缩略图，Storage 仅记录索引与偏好。应用自行控制照片文件合计不超过 12 MiB，并尊重容器实际剩余配额；达到数量或体积上限时，要求玩家选择删除或只保存到系统相册，不静默淘汰照片。

写入顺序为文件完成 → 索引完成 → 提示已保存；中途失败不把临时路径当持久照片。启动核对索引引用；索引读取失败不写默认值覆盖，照片丢失只标记该项不可用并允许移除。未完成保存的照片可在当前会话继续预览和导出，但明确标记「本次可见」。没有云同步承诺。

## 6. 技术路线与原项目复用

选择 **原生 JavaScript + WebGL 1 + GLSL ES 1.00 + HTML/CSS UI + Web Audio + 现有 esbuild**。这是设计者建议，理由是现有代码无引擎，目标景区规模可控，而且必须兼容较旧 WebView。WebGL 2 仅作能力增强，不出现必须依赖它的功能。原生渲染维护成本高于引擎，因此严格限制渲染特性，不自造通用场景编辑器或物理引擎。

WebGPU 渲染器和 WGSL 不做机械转译，也不作为移动主路径。旧版本仍保留供桌面参考；新实现放在独立 `minitool/` 目录，构建到该目录下 `dist/`，不覆盖根目录 `index.html` 和 `source/`。本轮不创建产品目录或安装依赖。

| 原有内容 | 处理 |
| --- | --- |
| 水色、光柱方向、鲸尾、岩拱、海藻与蝠鲼构图 | 保留为视觉参考，简化与重新布置 |
| math.js 的随机数、噪声、几何辅助 | 按函数抽取并记录来源，去除共享全局耦合 |
| world.js 中鱼、蝠鲼、鲸尾等几何生成 | 选择性抽取，降低细分；不照搬整个世界生成器 |
| WebGPU compute 地形与密度网格 | 替换为小型预生成地形网格及简单碰撞代理 |
| WGSL、水面 HDR、多重后处理、阴影管线 | 按视觉贡献重做少量 GLSL 效果，不逐项移植 |
| audio.js | 保留音色思路，改为独立音景模块；兼容旧构造方式，失败可静音运行 |
| quality.js 的动态降档思路 | 保留策略，存储改用平台接口，纹理和像素预算重定 |
| 横屏旋转、键鼠锁定、全屏、ES2022 内联构建 | 移除移动依赖，重建竖屏与 ES2017 外置脚本产物 |

首选渲染构成：不透明地形 / 岩石 / 生物 + 海藻顶点摆动 + 深度雾 + 包内小型焦散纹理 + 少量透明光柱 / 气泡。默认不使用动态阴影、全屏多级 bloom、体积光步进或 HDR 缓冲。柔光先用材质与低成本颜色曲线实现；透明效果按过绘制成本控制。

重复植物优先实例化（检测 ANGLE_instanced_arrays）；无扩展时使用预合并小网格和数量减半。不依赖顶点纹理读取、浮点 render target、32 位索引或 WebGPU compute。网格切块控制在 16 位索引范围。地形和配置在构建期生成并随经典 JS 打包，运行时不请求外网、不依赖 WASM 和 Worker。

模块边界：app 管状态与生命周期；renderer 管 GPU 与统一 render(scene, camera, target)；world 管固定种子、实体与简单碰撞；camera 管巡游和手动；photo 管取景和导出；audio 管声音；platform 管所有 xhs 调用、版本和失败；quality 管降档。使用直接模块组合，不加全局事件总线、ECS 或插件系统。

状态主线：准备 → 巡游 / 手动 / 停驻 → 取景 → 照片预览 → 返回取景或漫游。最近照片与设置是暂停覆盖层。隐藏和 GPU 丢失具有最高优先级；退出覆盖层不应重复注册监听或创建音频图。

## 7. 平台规则与核验依据

2026-11-20 已在线读取小红书官方文档，页面更新日期为 2026-11-19：
https://miniapp-sandbox.xiaohongshu.com/minitool/doc

当前明确支持 Canvas 2D / WebGL；未声明 WebGPU 支持，因此不把它作为产品基础。Android 产物按 ES2017 / Chrome 61 编译，CSS 基础层兼容该内核。脚本外置为包内 `.js`，不使用内联脚本、外链、动态执行、浏览器下载与 requestFullscreen。

保存相册使用 saveImageToPhotosAlbum（9.42+）；图片先用 writeTempFile 生成临时文件；发笔记用 postNote，精确参数依实施当天文档。元数据使用 Storage（9.46+），最近照片文件使用文件系统（9.49+）。临时路径不得持久化；文件配额、读写分片上限通过接口查询。

API 使用均独立检查版本、方法存在和调用结果。版本未知或新客户端缺方法 / 拒绝权限 / 调用失败，不得转而使用浏览器存储。平台不可用时仍能漫游和拍照预览；相册列表仅在本次会话保留，保存或发布按钮显示可用性，不伪造成功。普通浏览器使用明确的开发适配器，不能冒充容器验收。

与本地旧 API 快照比较，在线文档还新增 / 扩充了 AI 文本、窗口信息、定位、振动、陀螺仪、关注、分享和赞赏相关能力；存相册等接口版本与资源 CSP 规则也更明确。这些不应无依据沿用旧快照；首版只使用与照片和偏好直接相关的公开能力，不把内测接口作为前提。实际开发和上传前，应由平台当前开发口令加载对应规范，再核对在线规则。

## 8. 性能预算与失败处理

以下是待实测的工程目标，不是已达到的数据：

| 项目 | 默认档 | 低档 |
| --- | --- | --- |
| 稳态目标 | 30 FPS，帧耗时 P95 ≤ 40 ms | 24–30 FPS，P95 ≤ 50 ms |
| 绘制像素 | DPR ≤ 1.5 且不超过 1.5M 像素 | DPR ≤ 1 且不超过 0.8M 像素 |
| 每帧几何 / draw calls | ≤ 80k 三角形 / 80 | ≤ 40k / 45 |
| 常驻估算 GPU 资源 | ≤ 48 MiB | ≤ 28 MiB |
| 单张纹理 | ≤ 1024 边长，少量必要例外单独评审 | ≤ 1024 |
| 启动 | 容器打开至静态内容 P95 ≤ 1.5 s；点击进入至可漫游 P95 ≤ 5 s | 在指定验证机、相同包与明确冷热条件下测量 |
| 产物 | 完整 zip 目标 ≤ 2 MiB，超出先复核，不以小包牺牲核心画质 | 包体目标，不作为已核实平台硬限制 |

先低 / 中档启动。持续窗口内帧耗时超预算时，依次降像素、透明特效、远处植物，再缩视距；使用多秒观察窗口与滞后，场景生成 / 截图 / 后台恢复不纳入稳定帧率判断。首版不自动升档，避免来回波动。

WebGL 创建失败或多次恢复失败时显示包内静态景观与重试，明确当前是静态预览，不冒充可漫游游戏。context lost 暂停输入 / 模拟；恢复时重建资源并回到安全观景点，保留可用的照片索引。拍照和界面开关不得无限累积纹理。低档也保留鲸尾主体、海藻前景和色彩层次。

第二版只有在首版体验成立后再评估：沉船新景区、更多生物、不同光照和可选相片边框。不预先建设账号、云服务、交易或大型编辑工具。

## 10. 验证与发布准备

普通浏览器用于开发调试；创服平台模拟器、Android 真机和 iOS 真机必须分别验证同一份 zip。目标设备至少覆盖一台 4–6 GB Android、一台较新 Android，以及符合平台系统要求的 iPhone；实施时记录型号、系统、客户端、内核可观测信息和包哈希，不能从桌面帧率推断手机表现。

视觉：六个固定观景机位 + 一段完整巡游录屏；检查主体构图、海藻遮挡、闪烁、色带、透明排序、LOD 跳变和 UI 遮景；至少比较默认与低档。以用户明确的“瑰丽美景”为评审依据，不能只用几何数量代替画质。

功能：从进入 → 自动巡游 → 手动 → 取景 → 保存 → 最近照片 → 退出再进；另覆盖静音、减少动态、前后台切换、窄屏 / 安全区、权限拒绝、版本未知、SDK 缺失、配额耗尽、索引损坏和 WebGL 丢失。测试只围绕状态、边界、相机安全与照片数据一致性，不写镜像实现的无效单测。

性能：三分钟路径重复三轮并连续运行十分钟，分别报告帧耗时 P50 / P95 / P99、长停顿与触发点；记录截图时峰值和后台恢复，使用可用工具观察内存趋势与设备发热。冷启动与热启动各记录样本及条件；指标不足则明确未验，不写“流畅”结论。

交付产物：源码、可运行开发入口、经审计 zip、六机位与巡游记录、机型与性能报告、已知问题。上传、发布和账号操作不包含在本轮设计授权内；实际发布依用户后续指令。
