# 原版 Abyssal Garden 的小红书移植验证

2026-11-20。研究对象是本仓库根目录的原版场景，其上游是 [Noniv / Abyssal Garden](https://github.com/Noniv/abyssal-garden)，作者为 Maksymilian Dendra，许可为 MIT。研究以六个原始观景点的视觉和可游动体验为验收对象。

## 已验证

- 以本地提交 `20bd09f` 的原版源码为基线。根目录 `index.html` 为 99,184 字节。现有 esbuild 能把原版 JS 转译到 ES2017 / Chrome 61。转译产物仍需要 WebGPU 和 WGSL。
- 小红书本地模拟器 0.2.0 的 iPhone 预览里，平台桥已注入。本机的桌面浏览器实际完成了 WebGPU 计算并读回结果，也通过了 WebGL2 的 RG8 3D 纹理采样和 RGBA16F 绘制。该环境报告 3D 纹理最大边长 2048，RGBA16F 提供 1、2、4、8、16 倍采样档位。
- 将同一份原版场景的脚本外置，调整输入和横置页面，固定为原版低档，通过产物审计。模拟器中点击「潜入」后，原版 WebGPU 海床计算、鲸尾、海藻、水体光照和横置画面均出现在画面上。世界生成、碰撞、材质和着色器公式沿用原代码。
- 用户提供的截图记录了在小红书内展示的另一份成品及其功能入口。截图和本机模拟器均无法确定对方上线包使用哪个图形后端，也无法给出其机型覆盖范围。
- 真机尚未执行。模拟器的 iPhone 外观运行于本机桌面浏览器，实际 WebView 和宿主权限需在 Android 与 iOS 分别测试。

## 先保住原效果，再解决设备覆盖

1. **先验证原版 WebGPU。** 将原版 Low 包放入创服预览，分别在 Android 和 iOS 记录 WebGPU 适配器、设备创建、计算读回、真实场景首帧和后台恢复。失败时区分 API 不存在、适配器不可用、着色器编译和显存耗尽。官方公开基线列出 WebGL / WebGL2，未承诺 WebGPU。Safari 26 提供浏览器侧 WebGPU，但小红书最低 iOS 为 18.4，Safari 和桌面模拟器的结果都不能作为宿主覆盖承诺。[小红书容器能力](https://miniapp-sandbox.xiaohongshu.com/minitool/doc) [WebKit Safari 26](https://webkit.org/blog/17333/webkit-features-in-safari-26-0/)
2. **先移植海床生成，再移植可见画面。** 原版只有启动阶段的 `W_DENS` 必须依赖 GPU compute。现有 CPU 代码从密度场提取地形、生成岩体连通数据、碰撞体、海藻分布和体积纹理。保持生成顺序和随机种子。先用原版 WebGPU 离线生成密度或其衍生数据，按空间分块测实际压缩体积和解码峰值，再决定分发形式。全场密度为 512 × 80 × 512 个 float32，单份 80 MiB，初始计算缓冲、回读缓冲和 JS 副本会重复占用内存。原版 256 × 40 × 256 的 RG8 体积纹理本身约 5 MiB。不要直接将全密度场交给手机主线程或塞进上传包。若静态化的体积不合适，再验证使用 WebGL2 片元着色器分批计算并读回密度的路线。计算结果必须复查岩拱和隧道通行。
3. **WebGL2 按原管线逐通道复现。** 先对照地形、深度和阴影，再加海藻、焦散、鱼群和水面，再加体积光、原曝光与 bloom。将原 WGSL 逐段移植为 GLSL ES 3.00，保留原始参数。优先校对 WebGPU 与 WebGL 的裁剪深度、纹理 Y 方向、倒序 Z、批绘制的实例偏移、多级纹理生成和浮点帧缓冲。Cold Smoke 的 `01_gfx.js` 可借鉴实例绘制、深度比较与浮点能力检测。本项目的 WGSL 含独立资源绑定、计算入口及 3D 纹理，原框架的 SSL 翻译器不能整文件转换。
4. **用六个相同机位验收。** 用原 Low 档作为手机对照，在同分辨率比地形轮廓、鲸尾、沉船、紫色洞窟、焦散、光束和生物运动。测试时再调分辨率、叶片远距密度、阴影与光束采样。记录加载到可操作时间、帧间隔 p95、热机降档和前后台恢复。高画质是否可开由真机数据决定。

## 容器适配

原版竖屏以 CSS 旋转整个场景，并已在触控中变换坐标。移植时保留该机制，补齐旧内核的 `vh/vw`，去掉全屏及指针锁定，加入移动端上浮 / 下潜按钮。按 `getWindowInfo` 返回的安全区和原生菜单矩形换算到横置坐标，避免控件与容器按钮重叠。

最终产物使用根目录 `index.html` 和包内外置经典脚本。画质和累计时长使用容器 Storage。分享、存图和发笔记分别走对应公开 API。首轮验证以直接潜入、触控和画面为范围，排行榜及 AI 报告按实际开放权限单独评估。[小红书容器能力](https://miniapp-sandbox.xiaohongshu.com/minitool/doc)
